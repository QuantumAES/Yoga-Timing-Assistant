# ADR-003. Аудио-канал, модель громкости и режим «Не беспокоить»

**Статус:** принято · 2026-07-26
**Контекст:** снимает блокеры P0-5 и P0-6

---

## Контекст

Основной сценарий продукта (US-4): инструктор кладёт телефон на коврик и ведёт занятие, ориентируясь на слух. Если сигнал не прозвучал — продукт не выполнил свою единственную задачу.

ТЗ формулирует три требования к аудио:

1. §7 (код `AlertPlayer`): `AudioAttributes.USAGE_ASSISTANCE_SONIFICATION`;
2. §5.3: «Общая громкость сигналов, независимо от медиа-громкости, **через отдельный audio-stream**»;
3. §5.3 и Экран 6: «Режим "Не беспокоить" — приложение всё равно проигрывает сигналы», в UI — чекбокс «Игнорировать "Не беспокоить"».

## Проблема

### 1. Выбранный usage делает приложение немым

`USAGE_ASSISTANCE_SONIFICATION` маппится на `STREAM_SYSTEM`. Последствия:

- громкость привязана к системной, у многих OEM по умолчанию низкая или нулевая;
- полностью глушится в беззвучном режиме;
- не проходит через DND;
- на части прошивок регулируется тем же ползунком, что и звук нажатий клавиш, — пользователи выключают его намеренно.

Для сценария «телефон на коврике» это отказ продукта, причём тихий: приложение работает, сигналы «проигрываются», но их не слышно.

### 2. «Отдельный audio-stream» не существует как возможность

Android не позволяет приложению создать собственный аудиопоток с независимой регулировкой громкости. Доступен только выбор из фиксированного набора `USAGE_*`, каждый из которых отображается на системный стрим. Требование невыполнимо в буквальной формулировке.

### 3. Обход DND нельзя пообещать пользователю

Приложение не может односторонне игнорировать «Не беспокоить». Обход требует разрешения `ACCESS_NOTIFICATION_POLICY`, которое выдаётся вручную в специальном разделе системных настроек, и распространяется на каналы уведомлений, а не на произвольное воспроизведение звука. Чекбокс «Игнорировать "Не беспокоить"» обещает то, что приложение не контролирует.

## Решение

### Канал — STREAM_ALARM

```kotlin
private val attributes = AudioAttributes.Builder()
    .setUsage(AudioAttributes.USAGE_ALARM)
    .setContentType(AudioAttributes.CONTENT_TYPE_SONIFICATION)
    .build()
```

`USAGE_ALARM` даёт ровно те свойства, которых требует ТЗ:

| Требование ТЗ | STREAM_ALARM |
|---|---|
| Независимость от медиа-громкости | ✅ отдельный системный ползунок «Будильник» |
| Слышимость в беззвучном режиме | ✅ переживает ringer mode silent/vibrate |
| Прохождение через DND | ✅ в конфигурации DND по умолчанию будильники разрешены |
| Громкость, достаточная для зала | ✅ пользователи держат её высокой осознанно |

Тот же `AudioAttributes` устанавливается для `TextToSpeech` — иначе голос уйдёт в другой стрим и будет звучать тише сигналов.

### Громкость — программный гейн поверх системной

Ползунок «Громкость сигналов 0–100%» из Экрана 6 и поле `masterVolume` из модели данных реализуются как **множитель**, применяемый к воспроизведению, а не как управление системной громкостью:

```kotlin
soundPool.play(soundId, gain, gain, /* priority */ 1, /* loop */ 0, /* rate */ 1f)
// gain = (alert.volume ?: config.masterVolume) / 100f
```

Итоговая громкость = системная громкость будильника × наш гейн. Приложение никогда не меняет системные настройки пользователя.

В UI формулировка меняется с «Общая громкость сигналов» на **«Громкость сигналов (относительно громкости будильника)»**, чтобы пользователь понимал, почему ползунок на 100% может звучать тихо.

### DND — честная формулировка вместо невыполнимого обещания

Чекбокс «Игнорировать "Не беспокоить"» **убирается**. Вместо него:

- пояснительная строка: **«Сигналы используют канал будильника и звучат в беззвучном режиме»**;
- если система сообщает, что текущая политика DND блокирует будильники (`NotificationManager.currentInterruptionFilter`), показывается предупреждение с переходом в системные настройки DND.

Приложение сообщает пользователю правду о состоянии системы вместо того, чтобы обещать контроль, которого у него нет.

### Audio focus

```kotlin
AudioFocusRequest.Builder(AudioManager.AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK)
    .setAudioAttributes(attributes)
    .setOnAudioFocusChangeListener(listener)
    .build()
```

`MAY_DUCK` приглушает фоновую музыку на время сигнала — это и есть «ducking» из ТЗ §5.3. Фокус запрашивается на время оповещения и сразу отдаётся.

Потеря фокуса (входящий звонок) обрабатывается по правилу B-8: START/END откладываются до 10 с, WARNING пропускаются, таймер не останавливается.

### TTS и отсутствующий язык

Голосовые оповещения — заявленная ключевая фича (US-4), но русский голос на устройстве не гарантирован (блокер P0-10):

```
isLanguageAvailable(Locale) 
    LANG_AVAILABLE          → работаем
    LANG_MISSING_DATA       → предложить установку языкового пакета (ACTION_INSTALL_TTS_DATA)
    LANG_NOT_SUPPORTED      → канал VOICE недоступен: скрыт в редакторе,
                              существующие конфиги деградируют на SOUND,
                              разовое предупреждение пользователю
```

Проверка выполняется при инициализации движка TTS и при смене языка в настройках, а не в момент оповещения — узнать о проблеме посреди занятия недопустимо.

## Последствия

**Положительные**
- Основной сценарий продукта перестаёт зависеть от системной настройки, которую пользователи склонны выключать.
- Требования ТЗ «независимо от медиа» и «звучит в беззвучном режиме» выполняются штатными средствами платформы.
- UI больше не обещает невыполнимого.

**Отрицательные**
- Пользователь с намеренно тихим будильником получит тихие сигналы. Митигация: кнопка предпрослушивания на экране оповещений (уже есть в макете Экрана 5) даёт проверить громкость до занятия, а не во время.
- В строгой конфигурации DND («Полная тишина») будильники тоже глушатся. Митигация: детект и предупреждение, см. выше.
- Формулировки в ТЗ §5.3 и на Экране 6 требуют правки — учтено в `06-MVP-SCOPE.md`.
