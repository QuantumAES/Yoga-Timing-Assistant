# Звуковые ассеты оповещений

**Статус:** принято · 2026-07-28 (Фаза 4)
**Контекст:** реализует ADR-003, снимает P1-8 («лицензии на ассеты в репозитории»)

---

## 1. Решение

Сэмплы не скачиваются из библиотек CC0, а **порождаются скриптом**
[`scripts/generate-alert-sounds.py`](../scripts/generate-alert-sounds.py):

```bash
python3 scripts/generate-alert-sounds.py
# → core/audio/src/main/res/raw/alert_*.ogg
```

Синтез аддитивный: сумма затухающих синусоид с нецелыми отношениями частот —
именно нецелые призвуки дают металлу узнаваемый тембр, а разная скорость
затухания у высоких составляющих превращает удар в гонг, а не в писк.

## 2. Почему не библиотека готовых звуков

| | Готовый сэмпл CC0 | Синтез скриптом |
|---|---|---|
| Лицензия | нужно хранить файл лицензии, проверять происхождение, доверять загрузчику | автор — проект, вопрос закрыт |
| Ревью Play | риск претензии по чужому контенту | нечего предъявлять |
| Размер | типовой гонг в WAV — 1–3 МБ | **46 КиБ на все пять пресетов** |
| Правки | «сделать мягче» = искать другой файл | параметр в скрипте |
| Воспроизводимость | файл в git как чёрный ящик | тот же коммит → те же байты |

Плата за это — звук синтетический, а не записанный. Оценка: для сигнала
длительностью в две секунды, который слушают через комнату, разница между
записанным и синтезированным гонгом меньше, чем разница между двумя
устройствами. Если полевая проверка Фазы 8 покажет обратное, замена сэмпла —
это замена файла в `res/raw` без единой строки кода.

## 3. Пресеты

| `AlertSound` | Файл | Длит. | Роль |
|---|---|---|---|
| `SOFT_GONG` | `alert_soft_gong.ogg` | 3,2 с | старт и конец этапа в стандартной схеме |
| `SINGING_BOWL` | `alert_singing_bowl.ogg` | 4,5 с | тихий пресет: шавасана, медитация |
| `BELL` | `alert_bell.ogg` | 2,2 с | пресет «Максимум»: читается поверх музыки |
| `TONE` | `alert_tone.ogg` | 0,42 с | нейтральный короткий сигнал |
| `TICK` | `alert_tick.ogg` | 0,09 с | отсчёт последних секунд (на REST выключен, B-9) |

Формат — Ogg Vorbis, 44,1 кГц, моно. `SoundPool` держит их распакованными в
памяти и стартует без задержки на подготовку: задержка здесь — это опоздание
сигнала, то есть ровно то, чего продукт не имеет права допускать.

Длительности продублированы в коде (`SoundChannel.DURATIONS_MS`) — не для
воспроизведения, а для audio focus: `SoundPool` не сообщает об окончании, а
отдать фокус нужно после того, как звук отзвучал. Соответствие «пресет ↔ сэмпл ↔
длительность» проверяется юнит-тестом `SoundBankTest`.

## 4. Громкость

Пиковые уровни выставлены в скрипте по назначению, а не «в ноль»:
гонг 0,90 · чаша 0,78 · колокол 0,90 · тон 0,80 · тик 0,55. Тик громкостью с
гонг превращает отсчёт последних секунд в пытку.

Поверх этого работает программный гейн `masterVolumePercent` (ADR-003):
итоговая громкость = системная громкость будильника × гейн. Системные
настройки пользователя приложение не трогает.
