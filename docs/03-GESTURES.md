# Карта жестов и иерархия управления рабочим экраном

**Статус:** утверждено · 2026-07-26
**Контекст:** разрешает конфликт жестов, выявленный в `00-ANALYSIS.md` §5.1–5.2

---

## 1. Проблема

ТЗ назначает несовместимые обработчики одним и тем же жестам:

| Источник | Требование |
|---|---|
| §Экран 4 | «Тап по таймеру → режим фокуса» |
| §4.3, §6.3 | «Свайп для управления», «Управление жестами на рабочем экране» |
| §6.3 | «Lock-режим с двойным тапом» |
| §Экран 1 | «Свайп по карточке влево → удаление» |
| §Экран 2 | Drag-and-drop сортировка этапов + свайп-удаление в том же списке |

Ни один жест не привязан к режиму, поэтому в трёх состояниях рабочего экрана (обычный / фокус / lock) один и тот же тап должен делать разное — но правил нет.

Кроме того, макет Экрана 4 содержит **семь** интерактивных контролов, что противоречит собственным принципам ТЗ §1 и §6.1: «считывается за 1–2 секунды с расстояния 2–3 метров», «главные действия достижимы в 1–2 тапа».

---

## 2. Иерархия управления

Контролы ранжированы по фактической частоте использования на реальном занятии, а не по алфавиту макета.

| Ранг | Действие | Частота | Размещение | Размер |
|---|---|---|---|---|
| 1 | **Пауза / Возобновить** | несколько раз за занятие | центр нижней зоны | ≥ 88 dp |
| 2 | **След. этап** | раз в этап | справа от паузы | ≥ 72 dp |
| 3 | **−30 с / +30 с** | эпизодически | второй ряд | ≥ 64 dp |
| 4 | **‹ Пред. этап** | редко, при ошибке | второй ряд, слева | ≥ 64 dp |
| 5 | **🔒 Lock** | раз за занятие | верхний бар | 48 dp |
| 6 | **✕ Стоп** | раз за занятие | верхний бар | 48 dp |

```
┌──────────────────────────────────────┐
│  Хатха 60 мин            [🔒]  [✕]   │  ранг 5–6, верхний бар
│  ▓▓▓▓▓▓▓░░░░░░░░  Осталось 42 мин    │
│                                       │
│          ╭─────────────╮              │
│         │    А С А Н Ы   │            │
│         │                │            │  ← вся зона кольца = 
│         │     12:34      │            │    одна большая цель для тапа
│         │                │            │
│          ╰─────────────╯              │
│                                       │
│  Далее: 🔵 Балансы · 12:00            │
│  📝 Держим позиции по 5 циклов        │
│                                       │
│      ┌────────┐  ┌──────────────┐     │
│      │  ‹ −30 │  │      ⏸       │     │  ранг 1 — доминирует
│      └────────┘  └──────────────┘     │
│      ┌────────┐  ┌──────────────┐     │
│      │ +30 ›  │  │   След.  ›   │     │  ранг 2
│      └────────┘  └──────────────┘     │
│         ‹ Пред. этап                  │  ранг 4 — текстовая кнопка
└──────────────────────────────────────┘
```

Принцип: чем чаще действие, тем крупнее цель и тем ближе к большому пальцу. «Пауза» должна попадаться вслепую.

## 3. Карта жестов по режимам

Каждый жест определён во всех трёх режимах. Пустых клеток нет.

| Жест | Обычный | Фокус | Lock |
|---|---|---|---|
| **Тап по зоне таймера** | → войти в фокус | → выйти из фокуса | подсказка «Удерживайте для разблокировки» (без действия) |
| **Тап по кнопке** | действие кнопки | кнопок нет | игнорируется |
| **Свайп ←** | — | след. этап | игнорируется |
| **Свайп →** | — | пред. этап | игнорируется |
| **Свайп ↓** | — | выйти из фокуса | игнорируется |
| **Долгое нажатие (1 с) по таймеру** | — | — | **→ разблокировать** |
| **Двойной тап** | — | — | — |
| **Системная «Назад»** | диалог «Завершить занятие?» | выйти из фокуса | игнорируется + подсказка |

### Ключевые решения

**Свайпы работают только в режиме фокуса.** В обычном режиме экран занят кнопками, и свайп неизбежно конфликтовал бы с нажатием. В фокусе кнопок нет — свайп становится единственным и потому однозначным способом управления. Это разрешает противоречие между §Экран 4 и §6.3.

**Двойной тап не используется нигде.** ТЗ предлагал его для разблокировки (§6.3), но это ненадёжная защита в реальных условиях: телефон лежит на коврике, рядом занимающиеся, возможны случайные касания одеждой и ковриком. Заменён на удержание 1 с с визуальным индикатором прогресса — жест, который невозможно выполнить случайно.

**Долгое нажатие занято только под разблокировку.** Не назначается больше нигде, чтобы мышечная память работала однозначно.

## 4. Режим Lock

Активация: тап по 🔒 в верхнем баре. Мгновенно, без подтверждения.

Поведение:
- все касания игнорируются, кроме удержания по центру экрана;
- первое касание показывает ненавязчивую подсказку «Удерживайте для разблокировки» на 2 с;
- удержание рисует круговой индикатор заполнения; отпускание раньше 1 с отменяет;
- системная кнопка «Назад» игнорируется;
- таймер продолжает идти, оповещения продолжают срабатывать.

Индикация: иконка 🔒 в верхнем баре подсвечена, вокруг экрана — тонкая рамка акцентного цвета. Пользователь должен понимать, что экран заблокирован, с расстояния.

## 5. Режим фокуса

Вход: тап по зоне таймера в обычном режиме.

```
┌──────────────────────────────────────┐
│                                       │
│            А С А Н Ы                  │
│                                       │
│                                       │
│            12:34                      │  максимальный кегль
│                                       │
│                                       │
│         Далее: Балансы                │
│                                       │
│      ‹ свайп для смены этапа ›        │  подсказка, гаснет через 3 с
└──────────────────────────────────────┘
```

- Автозатемнение через 15 с бездействия (ТЗ §Экран 4).
- Любое касание возвращает полную яркость, отсчёт бездействия начинается заново.
- **Смена этапа считается таким же поводом осветить экран, что и касание,** и заводит те же 15 с. Раньше она подсвечивала экран на 2 с отдельным флагом; два флага с независимыми таймерами рассинхронизировались и оставляли экран негаснущим навсегда (полевая проверка 2026-07-31, третий круг). Одно состояние, которое нечему рассинхронизировать, стоит дешевле двухсекундной подсветки.
- Затемнение делается двумя слоями. `WindowManager.LayoutParams.screenBrightness` гасит подсветку окна — только своего, системные настройки не трогаются. Поверх экрана дополнительно ложится пелена: `screenBrightness` абсолютен, и в полутёмном зале, где системная яркость и без того около десяти процентов, приглушение попросту не видно. Видимую часть работы делает именно пелена, яркость окна — экономию батареи.

## 6. Согласование с остальными экранами

| Экран | Жест | Решение конфликта |
|---|---|---|
| Список профилей | свайп ← по карточке = удаление с Undo | Конфликта нет: вертикальная прокрутка списка и горизонтальный свайп по элементу различаются направлением |
| Редактор профиля, список этапов | drag-and-drop **только за ручку ⠿** | Свайп-удаление в этом списке **отключено** (в отличие от ТЗ §Экран 2): два горизонтальных жеста на одном элементе плюс перетаскивание — источник постоянных ложных срабатываний. Удаление этапа — через меню [⋮] |
| Редактор профиля | тап по этапу = открыть редактор | Не конфликтует: ручка перетаскивания имеет собственную зону касания |

---

## 7. Доступность

- Все жесты имеют кнопочную альтернативу. Управление свайпами в фокусе дублируется кнопками обычного режима — пользователь, которому свайпы недоступны, просто не входит в фокус.
- Для TalkBack режим фокуса объявляет действия через `CustomAccessibilityAction` («Следующий этап», «Предыдущий этап», «Выйти из фокуса»), а не полагается на распознавание свайпов.
- Разблокировка удержанием озвучивается: «Экран заблокирован. Удерживайте двумя секундами для разблокировки».
- Все цели касания ≥ 48 dp (требование ТЗ §6.3), на рабочем экране ≥ 64 dp.
