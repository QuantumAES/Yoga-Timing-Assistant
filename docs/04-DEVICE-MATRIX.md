# Матрица устройств и протокол приёмки фоновой работы

**Статус:** утверждено · 2026-07-26
**Назначение:** проверка риска R-1 на вехе **M2** и регрессионный прогон перед каждым релизом

---

## 1. Зачем это отдельный документ

Единственный способ провалить этот проект — обнаружить на неделе 12, что таймер молчит на половине телефонов. Эмулятор такого не покажет: он не воспроизводит поведение OEM-надстроек, которые и являются реальной угрозой.

Поэтому прогон матрицы — **не финальное тестирование, а go/no-go веха M2 на неделе 4–5**, до того как будет написан хоть один красивый экран.

---

## 2. Матрица

### 2.1. Обязательный минимум для M2

| Класс | Устройство | API | Прошивка | Что проверяет |
|---|---|---|---|---|
| **Эталон** | Pixel 6a / 7 (или эмулятор API 36) | 34–36 | AOSP | Базовая корректность на «чистом» Android |
| **Агрессивный OEM** | Xiaomi / Redmi | 33+ | MIUI / HyperOS | Худший реальный случай убийства процессов |
| **Массовый** | Samsung средний сегмент | 33+ | One UI | Sleeping apps, оптимизация в фоне |
| **Нижняя граница** | любое устройство или эмулятор | **26** | — | minSdk: ветки без FGS-type, без POST_NOTIFICATIONS |

> Без Xiaomi/MIUI веха M2 **не считается пройденной**. Это самая распространённая в РФ прошивка с самым агрессивным управлением фоном; проверять её последней — значит откладывать главный риск.

### 2.2. Расширение перед релизом

| Класс | Устройство | Что проверяет |
|---|---|---|
| Huawei / Honor | EMUI / MagicOS | Отсутствие GMS → TTS-фолбэк (P0-10) |
| Промежуточные API | эмуляторы API 30, 33 | Ветки разрешений: exact alarm (31+), POST_NOTIFICATIONS (33+), FGS type (34+) |
| Планшет / складной | любой | Landscape-вёрстка рабочего экрана |

### 2.3. Ветки поведения по версиям API

Одна и та же логика ведёт себя по-разному на трёх диапазонах — каждый проверяется отдельно.

| Диапазон | Особенности |
|---|---|
| **26–30** | Без runtime-разрешения на уведомления. Exact alarm без ограничений. FGS без объявления типа. Вибрация через устаревший API |
| **31–32** | `SCHEDULE_EXACT_ALARM` выдаётся при установке, но может быть отозвано пользователем. Ограничение на запуск FGS из фона |
| **33+** | `POST_NOTIFICATIONS` запрашивается. `USE_EXACT_ALARM` вместо `SCHEDULE_EXACT_ALARM` |
| **34+** | Обязателен `foregroundServiceType` + разрешение. Без них — краш |
| **35+** | Таймауты для части типов FGS (`specialUse` не подпадает) |

## 3. Протокол прогона

Тестовый профиль для всех сценариев — **«Матрица»**: 4 этапа по 3 минуты, оповещения по схеме «Стандарт» (старт, −2 мин, −1 мин, конец). Общая длительность 12 минут — достаточно для срабатывания Doze, но приемлемо для повторных прогонов.

### D-1. Базовый фоновый прогон

1. Запустить профиль «Матрица».
2. Свернуть приложение, заблокировать экран.
3. Не трогать устройство 12 минут.

**Ожидается:** все 16 оповещений срабатывают вовремя; финальное «Занятие завершено» звучит; уведомление в шторке актуально на протяжении всего прогона.

**Фиксируется:** отклонение каждого сигнала (по секундомеру или записи звука), наличие `DriftDetected` в логах.

### D-2. То же под форсированным Doze

```bash
adb shell dumpsys deviceidle enable
adb shell dumpsys deviceidle force-idle
# ... прогон ...
adb shell dumpsys deviceidle unforce
```

**Ожидается:** отклонения в пределах порога T-3 (±3 с) на эталоне и Samsung. Для MIUI допускается деградация при условии, что `DriftDetected` её зафиксировал.

### D-3. Убийство процесса

```bash
adb shell am kill ru.yogatimer     # мягкое, как это делает система
```
через 5 минут после старта занятия.

**Ожидается:** сервис воскрешается (`START_STICKY`) либо будится watchdog-алармом; сессия восстанавливается из снапшота; остаток корректен с отклонением < 2 с (критерий T-5).

### D-4. Принудительная остановка

```bash
adb shell am force-stop ru.yogatimer
```

**Ожидается:** приложение НЕ воскресает (это корректное поведение — пользователь явно остановил). При следующем открытии — предложение «Продолжить занятие?», если прошло < 5 мин.

### D-5. Входящий звонок

Позвонить на устройство в момент, когда до оповещения остаётся ~30 с. Ответить, поговорить 1 минуту, положить трубку.

**Ожидается:** таймер продолжает идти; поведение оповещений соответствует правилу B-8 (START/END откладываются до 10 с, WARNING пропускаются); после звонка отсчёт корректен.

### D-6. Перезагрузка

Перезагрузить устройство в середине занятия.

**Ожидается:** сессия не восстанавливается; при открытии — уведомление «Занятие было прервано перезагрузкой» (B-11); приложение не падает и не показывает мусорное состояние.

### D-7. Смена системного времени

Перевести системное время на +2 часа во время занятия.

**Ожидается:** отсчёт не изменился ни на секунду (B-14) — проверка того, что монотонные часы действительно используются везде.

### D-8. Отзыв разрешений

Отозвать разрешение на точные будильники (Настройки → Приложения → Будильники и напоминания) и запустить занятие.

**Ожидается:** приложение работает; показан баннер «Оповещения могут запаздывать» с переходом в настройки; watchdog переключился на неточный аларм.

### D-9. Фоновая музыка

Запустить музыку в стороннем плеере, начать занятие.

**Ожидается:** музыка приглушается на время сигнала (ducking) и восстанавливает громкость; сигналы отчётливо слышны поверх музыки.

### D-10. Беззвучный режим и DND

Перевести устройство в беззвучный режим, затем включить DND, запустить занятие.

**Ожидается:** сигналы слышны в обоих случаях (следствие ADR-003 — канал будильника). В режиме DND «Полная тишина» — сигналы могут глушиться, но приложение обязано это обнаружить и предупредить.

### D-11. Батарея

Полный 90-минутный профиль при выключенном экране, с замером через `dumpsys batterystats`.

**Ожидается:** расход < 5% (критерий N-3).

## 5. Критерий прохождения M2

Веха считается взятой, если **одновременно**:

1. На эталонном устройстве все тесты D-1…D-11 пройдены без оговорок.
2. На Samsung тесты D-1…D-6 пройдены при снятой оптимизации батареи.
3. На Xiaomi/MIUI при снятой оптимизации батареи занятие проходит целиком без потери сигналов.
4. На Xiaomi/MIUI при включённой оптимизации — деградация допустима, но **обнаружена и показана пользователю** (`DriftDetected` → баннер).
5. Тест D-7 (смена времени) пройден на всех устройствах без единого отклонения.

### Если M2 не взята

Не «дорабатываем и надеемся», а выполняем заранее определённый план:

| Симптом | Действие |
|---|---|
| MIUI убивает процесс даже при снятой оптимизации | Ввести в онбординг обязательный шаг «Автозапуск» с инструкцией под конкретную прошивку; понизить обещания в описании в Play |
| Сигналы теряются на всех устройствах в Doze | Пересмотр ADR-001: рабочий экран обязан оставаться на переднем плане, фоновый режим объявляется best-effort |
| Отклонения > 3 с на эталоне | Дефект в движке, а не в платформе — чинится в коде, веха переносится |

Решение принимается **на неделе 5**, когда стоимость разворота ещё измеряется днями, а не месяцами.
