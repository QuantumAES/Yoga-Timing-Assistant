# Техническое задание на разработку Android-приложения «Yoga Timing Assistant»

*(Рабочее название — можно заменить)*

---

## 1. Резюме и роли анализа

Ниже — комплексный разбор от лица трёх экспертов, сведённый в единое ТЗ.

**Как аналитик:** ключевая ценность — помочь инструктору вести занятие «по плану», не глядя постоянно на экран. Значит, приоритет — **аудио- и тактильные оповещения**, а не визуальные.

**Как UI/UX-дизайнер:** интерфейс во время занятия должен быть «glanceable» — считываться за 1–2 секунды с расстояния 2–3 метров, крупные элементы, минимум текста.

**Как программист:** приложение должно надёжно работать в фоне, при заблокированном экране, переживать сворачивания и звонки. Это диктует выбор стека.

---

## 2. Цели и задачи продукта

### 2.1. Бизнес-цель
Дать инструкторам по йоге инструмент для точного контроля тайминга занятия по заранее подготовленному сценарию (профилю).

### 2.2. Функциональные задачи
- Создание и хранение **настраиваемых профилей занятий** под заданное общее время.
- Разбивка занятия на **этапы/блоки** (разминка, асаны, шавасана и т.д.).
- Гибкая система **оповещений** (звук, вибрация, голос, экран).
- Управление таймером во время занятия одним касанием.
- Работа без интернета (офлайн-first).

---

## 3. Целевая аудитория и сценарии

### 3.1. Пользователи
- Инструкторы йоги (индивидуальные и групповые занятия).
- Возможное расширение: пилатес, стретчинг, медитация, дыхательные практики.

### 3.2. Основные сценарии (User Stories)

| # | Сценарий |
|---|----------|
| US-1 | Как инструктор, я создаю профиль «Хатха 60 мин» с этапами, чтобы использовать его на регулярных занятиях. |
| US-2 | Как инструктор, я запускаю профиль и получаю сигналы о смене этапов, не отвлекаясь на телефон. |
| US-3 | Как инструктор, во время занятия я хочу продлить/сократить текущий этап на ходу. |
| US-4 | Как инструктор, я хочу поставить телефон на коврик и слышать голосовое оповещение «Осталось 2 минуты до шавасаны». |
| US-5 | Как инструктор, я хочу быстро дублировать профиль и подправить его под нового клиента. |

## 4. Функциональные требования

### 4.1. Профили занятий

Профиль содержит:
- Название, иконку/цвет, категорию.
- **Общее время занятия** (задаётся вручную ИЛИ вычисляется как сумма этапов).
- Два режима работы:
  - **Режим «Сумма этапов»** — общее время = сумма блоков.
  - **Режим «Фиксированное общее время»** — пользователь задаёт итог, а приложение помогает распределить/предупреждает о расхождении.
- Список этапов (блоков).
- Настройки оповещений (наследуются, могут переопределяться на уровне этапа).

**Действия с профилями:** создать, редактировать, дублировать, удалить, экспорт/импорт (JSON), избранное, сортировка.

### 4.2. Этапы (блоки) занятия

Каждый этап:
- Название (например: «Разминка», «Приветствие солнцу», «Балансы», «Шавасана»).
- Длительность.
- Цвет/иконка (для быстрой визуальной идентификации).
- Тип: *обычный*, *переходный*, *отдых*, *свободный* (без фиксированного времени).
- Индивидуальные оповещения (опционально).
- Заметка/подсказка инструктору (текст, отображается на экране этапа).

### 4.3. Экран проведения занятия (главный экран таймера)

Отображает:
- **Крупный таймер** текущего этапа (обратный отсчёт).
- Название текущего этапа + прогресс-кольцо.
- Название следующего этапа + его длительность.
- Общий прогресс занятия (полоса + «осталось всего X мин»).
- Кнопки: Пауза/Старт, Следующий этап, Предыдущий этап, +30 сек / −30 сек, Стоп.
- Опционально: «Пропустить этап», «Растянуть текущий».

**Режим фокуса:** гигантские цифры на весь экран, свайп для управления, автоматическое затемнение.

## 5. Система оповещений (ключевая фича)

### 5.1. Типы каналов оповещений
1. **Звуковые** — набор пресетов (мягкий гонг, чаша, колокольчик, тон). Загрузка своих файлов.
2. **Голосовые (TTS)** — синтез фраз: «Осталась 1 минута», «Переход к шавасане». Поддержка кастомных фраз.
3. **Вибрация** — паттерны (одиночная, двойная, длинная).
4. **Визуальные** — вспышка цвета экрана / фонарика (для шумных залов).

### 5.2. Триггеры оповещений (оптимальная настройка — рекомендация эксперта)

Предлагаю следующую **дефолтную схему**, проверенную для практик:

| Триггер | Канал по умолчанию | Назначение |
|---------|-------------------|------------|
| Старт этапа | Мягкий гонг + голос названия этапа | Смена активности |
| За 2 мин до конца этапа | Тихая одиночная вибрация | Начать сворачивать блок |
| За 1 мин до конца | Двойная вибрация + опц. голос | Финальное предупреждение |
| За 10 сек | Обратный отсчёт (опционально) | Точная посадка |
| Конец этапа / переход | Гонг + голос следующего этапа | Смена |
| Особый: вход в шавасану | Тихая чаша (без резких звуков) | Не нарушать релаксацию |
| Конец занятия | Завершающий гонг + «Занятие завершено» | Финал |

**Гибкость:** пользователь может для любого этапа:
- включать/выключать любой триггер;
- менять момент срабатывания (за N сек/мин);
- выбирать канал и звук;
- задать «тихий этап» (например, медитация — только вибрация).

### 5.3. Глобальные настройки оповещений
- Общая громкость сигналов (независимо от медиа-громкости, через отдельный audio-stream).
- Режим «Не беспокоить» — приложение всё равно проигрывает сигналы.
- Работа при заблокированном экране и в фоне.
- Прерывание/понижение фоновой музыки на время сигнала (audio focus ducking).

## 6. UI/UX

### 6.1. Дизайн-принципы
- **Material Design 3** (Material You), поддержка динамических цветов.
- **Тёмная тема по умолчанию** (щадит глаза в приглушённом свете зала).
- Крупная типографика, высокий контраст.
- Минимум вложенности: главные действия достижимы в 1–2 тапа.
- Экран таймера удерживает экран включённым (Wake Lock) с опцией автозатемнения.

### 6.2. Карта экранов
1. **Список профилей** (главный) — карточки, поиск, кнопка «+».
2. **Редактор профиля** — общие настройки + список этапов (drag-and-drop сортировка).
3. **Редактор этапа** — длительность, оповещения, заметки.
4. **Экран занятия (Timer/Run)** — основной рабочий экран.
5. **Настройки** — звуки, вибрация, TTS-голос, тема, единицы.
6. **Онбординг** (3–4 слайда при первом запуске).

### 6.3. Эргономика для «в движении»
- Landscape и Portrait режимы.
- Крупные тач-зоны (min 48dp, для рабочего экрана — 64dp+).
- Управление жестами на рабочем экране.
- Опция запрета случайного касания (lock-режим с двойным тапом).

## 7. Архитектура и технический стек

### 7.1. Рекомендуемый стек

| Слой | Технология | Обоснование |
|------|-----------|-------------|
| Язык | **Kotlin** | Стандарт Android, лаконичность, null-safety |
| UI | **Jetpack Compose** + Material 3 | Быстрая декларативная вёрстка, адаптивность |
| Архитектура | **MVVM + Clean Architecture** (слои: data / domain / presentation) | Тестируемость, масштабируемость |
| DI | **Hilt** | Стандарт для DI в Android |
| Асинхронность | **Coroutines + Flow / StateFlow** | Реактивный таймер и обновление UI |
| Локальная БД | **Room** | Хранение профилей и этапов офлайн |
| Фоновая работа | **Foreground Service** | Надёжный таймер при свёрнутом/заблокированном приложении |
| Оповещения | **AlarmManager (exact) / собственный service-loop** | Точность срабатывания |
| Аудио | **SoundPool** (короткие сигналы) + **MediaPlayer**, **TextToSpeech API** | Низкая задержка звуков + голос |
| Настройки | **DataStore (Preferences)** | Современная замена SharedPreferences |
| Навигация | **Navigation Compose** | Единый граф навигации |
| Сериализация | **Kotlinx.serialization** | Экспорт/импорт профилей |

### 7.2. Ключевое архитектурное решение — таймер

**Проблема:** обычный корутин-таймер «замерзает» при Doze/сворачивании.

**Решение:**
- Таймер запускается в **Foreground Service** с постоянным уведомлением (управление: пауза/следующий/стоп прямо из шторки).
- Расчёт времени ведётся по **абсолютным меткам времени** (System.currentTimeMillis / elapsedRealtime), а не по «тикам» — устойчиво к паузам системы.
- Оповещения планируются заранее через **AlarmManager (setExactAndAllowWhileIdle)** — гарантированное срабатывание даже в Doze.
- WakeLock только при активном занятии, освобождается по завершении.

### 7.3. Модель данных (упрощённо)

```
Profile
 ├─ id, name, colorTag, category, iconId
 ├─ totalDurationMode (SUM | FIXED)
 ├─ fixedTotalDuration (nullable)
 ├─ defaultAlertConfig
 └─ stages: List<Stage>

Stage
 ├─ id, profileId, order
 ├─ name, colorTag, type
 ├─ durationSec
 ├─ note
 └─ alertConfig (nullable → наследует от Profile)

AlertConfig
 ├─ startAlert: Alert
 ├─ warningAlerts: List<Alert>   // «за 2 мин», «за 1 мин» и т.д.
 └─ endAlert: Alert

Alert
 ├─ enabled
 ├─ offsetSec        // за сколько до конца
 ├─ channel (SOUND | VOICE | VIBRATION | FLASH)
 ├─ soundId / ttsPhrase / vibrationPattern
 └─ volume
```

## 8. Нефункциональные требования

- **Платформа:** Android 8.0+ (API 26+).
- **Офлайн-first:** полный функционал без интернета.
- **Производительность:** запуск < 2 сек, отклик UI < 100 мс.
- **Надёжность таймера:** погрешность < 1 сек за занятие.
- **Энергоэффективность:** минимальный расход, WakeLock только по необходимости.
- **Локализация:** RU/EN (архитектура готова к расширению).
- **Доступность:** поддержка крупного шрифта, TalkBack на неигровых экранах.
- **Приватность:** данные хранятся локально; GDPR-совместимость при добавлении облака.

## 10. Критерии приёмки (примеры)

- Профиль на 60 мин из 6 этапов создаётся и воспроизводится с корректными переходами.
- При заблокированном экране и свёрнутом приложении все оповещения срабатывают вовремя (± 1 сек).

### Компоненты и поведение

| Элемент | Поведение |
|---------|-----------|
| Поле «Название» | Обязательное; валидация на пустоту при сохранении |
| Режим времени | Радио: переключение SUM ↔ FIXED |
| Итого | В режиме SUM — считается автоматически. В режиме FIXED — показывает расхождение (см. ниже) |
| Список этапов | Drag-and-drop (⠿) для сортировки; свайп-удаление с Undo |
| Тап по этапу | Открыть **Редактор этапа** |
| [⋮] на этапе | Дублировать / Удалить |
| «Добавить этап» | Открыть Редактор этапа в режиме создания |
| «Оповещения по умолчанию» | Открывает конфиг Alert для всего профиля |
| [✓] Сохранить | Валидация → запись в Room → возврат к списку |

### Логика режима «Фиксированное время»
```
Задано: 01:00:00
Сумма этапов: 00:58:00
→ Показать: "⚠ Не распределено: 2 мин"
   [ Распределить автоматически ]  ← кнопка: раскидать пропорционально
```
- Если сумма > фиксированного → красный индикатор «Превышение на X мин».
- Кнопка авто-распределения масштабирует длительности пропорционально.

|---------|-----------|
| Гигантский таймер | Обратный отсчёт этапа. Читаемость с 2–3 м |
| Прогресс-кольцо | Заполняется по мере прохождения этапа; меняет цвет на последней минуте |
| Общий прогресс | Полоса + «осталось всего X мин» |

| Wake Lock | Экран не гаснет; через 15 сек бездействия — затемнение до 10% яркости |

### Состояния
- **Running** — идёт отсчёт.
- **Paused** — таймер заморожен, кольцо пульсирует.
- **Transition** — короткая анимация + оповещение смены этапа.
- **Finished** — экран «Занятие завершено 🙏» + кнопки «В начало» / «Повторить».

## 2. Схема таблиц (SQL / Room)

### Таблица `profiles`

```sql
CREATE TABLE profiles (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    name              TEXT    NOT NULL,
    category          TEXT    NOT NULL DEFAULT 'GENERAL',
    color_tag         TEXT    NOT NULL DEFAULT '#4CAF50',
    icon_id           TEXT,

    default_alert_id  INTEGER NOT NULL,

    FOREIGN KEY (default_alert_id) REFERENCES alert_configs(id) ON DELETE CASCADE
);
```

### Таблица `stages`

```sql
CREATE TABLE stages (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    profile_id       INTEGER NOT NULL,
    name             TEXT    NOT NULL,
    type             TEXT    NOT NULL DEFAULT 'NORMAL', -- NORMAL|TRANSITION|REST|FREE
    color_tag        TEXT    NOT NULL DEFAULT '#4CAF50',
    duration_sec     INTEGER NOT NULL DEFAULT 0,        -- 0 для FREE
    note             TEXT,
    sort_order       INTEGER NOT NULL,
    alert_config_id  INTEGER,                            -- nullable = наследование
    FOREIGN KEY (profile_id) REFERENCES profiles(id) ON DELETE CASCADE,
    FOREIGN KEY (alert_config_id) REFERENCES alert_configs(id) ON DELETE SET NULL
);

CREATE INDEX idx_stages_profile ON stages(profile_id, sort_order);
```

### Таблица `alert_configs`

```sql
CREATE TABLE alert_configs (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    preset_type    TEXT    NOT NULL DEFAULT 'STANDARD', -- STANDARD|SILENT|VIBRO_ONLY|MAX|CUSTOM
    master_volume  INTEGER NOT NULL DEFAULT 70          -- 0..100
);
```

### Таблица `alerts`

```sql
CREATE TABLE alerts (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    alert_config_id   INTEGER NOT NULL,
    trigger_type      TEXT    NOT NULL,   -- START | WARNING | END
    enabled           INTEGER NOT NULL DEFAULT 1,
    offset_sec        INTEGER NOT NULL DEFAULT 0,  -- за сколько до конца (для WARNING/END)
    channel_mask      INTEGER NOT NULL DEFAULT 1,  -- битовая маска каналов
    sound_id          TEXT,                         -- id пресета или uri
    tts_template      TEXT,                         -- "Переход к: {next}"
    vibration_pattern TEXT    DEFAULT 'SINGLE',     -- SINGLE|DOUBLE|LONG
    volume            INTEGER,                       -- null = наследует master_volume
    FOREIGN KEY (alert_config_id) REFERENCES alert_configs(id) ON DELETE CASCADE
);

CREATE INDEX idx_alerts_config ON alerts(alert_config_id);
```

### Битовая маска каналов (`channel_mask`)

```
0b0001 = 1  → SOUND
0b0010 = 2  → VOICE (TTS)
0b0100 = 4  → VIBRATION
0b1000 = 8  → FLASH (экран/фонарик)

Пример: Звук + Вибрация = 1 | 4 = 5
```

## 1. Диаграмма состояний (State Machine)

```
                    ┌──────────────┐
                    │     IDLE     │  ← экран открыт, занятие не начато
                    └──────┬───────┘
                           │ start()
                           ▼
                    ┌──────────────┐
        ┌──────────►│   RUNNING    │◄──────────┐
        │           └──┬───┬───┬───┘           │
        │ resume()     │   │   │  stageEnd()   │ prev()/next()
        │              │   │   └──────────┐    │
        │        pause()  finish()        ▼    │
        │              │   │        ┌──────────┴───┐
    ┌───┴──────┐       │   │        │  TRANSITION  │
    │  PAUSED  │◄──────┘   │        └──────┬───────┘
    └──────────┘           │               │ auto (после анимации)
                           │               ▼
                           │        (следующий этап → RUNNING)
                           ▼
                    ┌──────────────┐
                    │   FINISHED   │  ← все этапы пройдены
                    └──────┬───────┘
                           │ restart() / exit()
                           ▼
                        (IDLE / выход)
```

### Описание состояний

| Состояние | Описание | Активные действия |
|-----------|----------|-------------------|
| **IDLE** | Профиль загружен, отсчёт не идёт | start() |
| **RUNNING** | Идёт отсчёт текущего этапа | pause, next, prev, ±30с, stageEnd, finish |
| **PAUSED** | Отсчёт заморожен | resume, next, prev, stop |
| **TRANSITION** | Кратковременный переход между этапами (анимация + оповещение) | auto → RUNNING |
| **FINISHED** | Занятие завершено | restart, exit |

```kotlin
class AlarmScheduler @Inject constructor(
    @ApplicationContext private val ctx: Context
) {
    private val am = ctx.getSystemService<AlarmManager>()!!
    private val scheduled = mutableListOf<Int>()

    fun scheduleExact(triggerAtMs: Long, alertId: Long, requestCode: Int) {
        val pi = buildPendingIntent(alertId, requestCode)
        // Android 12+: проверка canScheduleExactAlarms()
        if (Build.VERSION.SDK_INT >= 31 && !am.canScheduleExactAlarms()) {
            // fallback → setAndAllowWhileIdle (неточный) + предупредить юзера
        }
        am.setExactAndAllowWhileIdle(
            AlarmManager.ELAPSED_REALTIME_WAKEUP,
            SystemClock.elapsedRealtime() + (triggerAtMs - System.currentTimeMillis()),
            pi
        )
        scheduled += requestCode
    }

    fun cancelAll() {
        scheduled.forEach { am.cancel(buildPendingIntent(0, it)) }
        scheduled.clear()
    }
}
```

## 7. AlertPlayer — воспроизведение оповещений по каналам

```kotlin
class AlertPlayer @Inject constructor(
    @ApplicationContext private val ctx: Context,
    private val ttsEngine: TtsEngine
) {
    private val soundPool = SoundPool.Builder()
        .setMaxStreams(4)
        .setAudioAttributes(
            AudioAttributes.Builder()
                .setUsage(AudioAttributes.USAGE_ASSISTANCE_SONIFICATION)
                .setContentType(AudioAttributes.CONTENT_TYPE_SONIFICATION)
                .build()
        ).build()

    fun play(alert: ResolvedAlert) {
        if (!alert.enabled) return

        // Запрос audio focus с ducking (приглушить фоновую музыку)
        requestAudioFocusTransient()

        if (alert.hasChannel(Channel.SOUND))     playSound(alert.soundId, alert.volume)
        if (alert.hasChannel(Channel.VIBRATION)) vibrate(alert.vibrationPattern)
        if (alert.hasChannel(Channel.VOICE))     ttsEngine.speak(resolveTemplate(alert.ttsTemplate))
        if (alert.hasChannel(Channel.FLASH))     flashScreen()
    }

    private fun resolveTemplate(tpl: String?): String =
        tpl?.replace("{stage}", currentStageName)
            ?.replace("{next}", nextStageName) ?: ""
}
```

## 8. Обработка граничных случаев (Edge cases)

| Ситуация | Решение |
|----------|---------|
| Входящий звонок | Audio focus теряется → оповещения ставятся в очередь / пропускаются; таймер идёт по clock |
| Система убила сервис | `START_STICKY` + восстановление сессии из persisted-снимка (DataStore) |
| Перезагрузка устройства | Сессия не восстанавливается (осознанное решение) — уведомить пользователя |
| Пользователь свернул приложение | Сервис + уведомление продолжают работу |
| ±30 сек ушли в минус | `coerceAtLeast(0)` → мгновенный переход к следующему этапу |
| Doze-режим | AlarmManager exact + `AllowWhileIdle` пробивает Doze для оповещений |
| Экран заблокирован | WakeLock partial (только CPU), экран не будим кроме FLASH-оповещения |
| Батарея оптимизирует приложение | Онбординг просит исключение; предупреждение при первом запуске сессии |
| Нет разрешения exact alarm (A12+) | Fallback на inexact + баннер «Оповещения могут запаздывать» |
| «Свободный» этап (FREE) | Таймер считает вверх (elapsed), завершение только по кнопке «Далее» |
